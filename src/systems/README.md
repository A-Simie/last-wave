# Gameplay systems

`InteractionSystem.ts` selects the nearest enabled, available, visible target in range and publishes prompt/message state. An optional `isAvailable` predicate hides collected story targets while preserving their solid geometry. Eligible actions show a timed message or invoke a scene-owned callback, then publish the stable target ID through `onInteract`. Dialogue, cutscenes, journal, checkpoint controls, and scene transitions suspend selection and further interactions.

`DialogueSystem.ts` owns one authored conversation, validates node/choice links, and publishes speaker/text/choice state. Valid selections emit dialogue/node/choice IDs through `onChoice`. It is independent of rendering and browser input. Authored, progress-aware guide content lives in `src/data/dialogues.ts`.

`CutsceneSystem.ts` owns one reader-paced sequence of speaker/text/shot beats. Stable sequence/beat IDs reject stale input. Finishing or skipping emits one completion event; cancellation and destruction do not. It owns no camera, timers, or DOM. The episode composition maps completion into quest progress, `Game.ts` coordinates input, and `CutscenePanel.ts` renders accessible captions/skip/reduced-motion controls.

`QuestSystem.ts` tracks one authored quest with inactive/active/completed state. Ordered objectives remain the default; `order: 'any'` supports free-order, one-shot discoveries. It consumes interaction, dialogue-choice, cutscene-complete and control-practiced events, ignores duplicates or invalid ordered progress, and releases progress/listeners on destruction. Snapshots contain canonical completed IDs: an ordered prefix for sequential quests or any valid unique subset for free-order quests. Restoration validates atomically and publishes changed sets without replaying gameplay events. Definitions live in `src/data/quests.ts` and `src/episodes/episode-01/{opening,entry,beach}.ts`. The HUD only renders snapshots.

`InventorySystem.ts` owns unique collected item IDs from a validated catalog, publishes copied snapshots in acquisition order, and rejects duplicate/unknown pickups. The optional item `kind` distinguishes clues (default) from protected quest belongings; there is no discard/consume operation. Restoration validates all saved IDs before replacing the collection. Scene composition owns acquisition rules. `Game.ts` connects inventory snapshots to the HUD and journal; reset/destruction clears the model and callbacks.

`SaveSystem.ts` reads, validates, writes, and deletes one version-4 checkpoint through an injected storage accessor. Versions 1–3 migrate in memory without rewriting stored bytes. The engine-independent scene contract in `src/scenes/FoundationState.ts` validates all four quests, belongings/pass prerequisites, area and static geometry; only newly occupied legacy positions relocate. Beach discoveries require completed admission and the beach area. `FoundationScene.ts` captures/restores model state and player position; `SceneManager.ts` stages scene replacement and retains the live scene on construction or activation failure. `Game.ts` owns manual save/load actions and modal/input coordination.
